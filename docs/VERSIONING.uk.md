# Політика версій і тегів

Версії продукту та release-процесу незалежні.

## Версія продукту

`VERSION` містить трьохкомпонентну семантичну версію лінії пакетів `iros2j`:

```text
MAJOR.MINOR.PATCH
```

Namespace пакета вже визначає покоління ROS: `2` в `iros2j` означає ROS 2, а
`j` — Jazzy. Тому перша версія пакетів `iros2j` — `1.0.0`, а не `2.1.0.0`.

- `MAJOR`: несумісна зміна namespace пакетів, структури, API або публічної
  поведінки в межах цього покоління ROS.
- `MINOR`: сумісне додавання пакета або функціональності.
- `PATCH`: сумісне виправлення.

Git-теги продукту додають покоління ROS перед версією пакета:

```text
v<ROS_GENERATION>.<MAJOR>.<MINOR>.<PATCH>
```

Отже пакет `iros2j` версії `1.0.0` публікується з Git-тегом `v2.1.0.0`.
Початкова `2` належить лише тегу репозиторію та release identity і не
дублюється у версії пакета.

Debian-форма — `<package-version>-<debian-revision>+deb13`, спочатку
`1.0.0-1+deb13`. Збірка лише з виправленням пакування може підвищити Debian
revision, але публічна заміна завжди отримує новий незмінний Git-тег і release;
опубліковані assets не перезаписуються.

Усі пакети одного snapshot дистрибутива мають однакову версію дистрибутива.
Upstream-версія кожного ROS-пакета окремо фіксується в component manifest.

## Версія процесу

`PROCESS_VERSION` — трьохкомпонентна семантична версія регламентів, схем,
валідаторів, скриптів збірки/публікації, issue forms та release-автоматизації.
Її теги мають формат `process-v<MAJOR>.<MINOR>.<PATCH>`.

- `MAJOR`: несумісна зміна workflow, схеми, підтримуваної платформи або gate.
- `MINOR`: сумісна можливість або нова обов'язкова вимога.
- `PATCH`: сумісне виправлення чи уточнення.

Зміна лише процесу не змінює `VERSION`. Зміна лише продукту не змінює
`PROCESS_VERSION`. Якщо одне завдання змінює обидва, обидва нові теги можуть
вказувати на той самий коміт після проходження всіх gate.

## Незмінні теги

Тег є результатом успішного gate, а не його вхідними даними. Опубліковані
продуктові та процесні теги не видаляються, не пересуваються й не
використовуються повторно. Дефект після створення тегу потребує нової версії
та нового тегу.
