# Участь у розробці

Перед зміною пакування, збірки, тестування або випуску прочитайте
[індекс документації](docs/README.uk.md).

Зміни регламентів, обов'язкових контрольних списків, release metadata, схем,
issue forms, валідаторів, скриптів публікації або автоматизації є змінами
процесу. Для них потрібно:

1. одночасно оновити канонічний англійський документ та його відповідник
   `.uk.md`;
2. оновити `PROCESS_VERSION` за правилами `docs/VERSIONING.md`;
3. описати зміну в `CHANGELOG.md` у розділі `Process`;
4. пройти перевірки документації та відповідні перевірки release-процесу;
5. закомітити зміни й опублікувати новий незмінний тег `process-v*` до
   використання зміненого процесу для продуктового релізу.

Реалізація продукту має відповідати `docs/PACKAGE_POLICY.md` та
`docs/RELEASE_PROCESS.md`. Кожне implementation-завдання також має
дотримуватися пов'язаного GitHub/ClickUp workflow з
`docs/TASK_MANAGEMENT.md`.
Оцінка, time tracking, записи operations/errors та task completion reports
мають відповідати `docs/ESTIMATION_AND_PERFORMANCE.md`.
